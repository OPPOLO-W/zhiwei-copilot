# 阶段 A 基线报告：难题集与硬幻觉指标

> 检查点：`v5-baseline-50q` → 本报告 → `v6-hard-eval`
> 题集：`data/eval/questions_hard.jsonl`（20 题）｜ 重复次数：3 ｜ 后端：`KG_BACKEND=memory`
> 日期：2026-11-18

---

## 1. 一句话结论

**基线可用，阶段 A 通过，可以进阶段 B。** 但基线本身暴露了 6 个真缺陷，
其中 3 个已在阶段 A 内修掉、3 个留给阶段 B。最重要的发现不是「LLM 有没有用」，
而是**现有 50 题的 0.98 是判定宽造成的假象**：在 8 道「前提已排除」的题上，
规则系统的答案准确率是 8/8，而首选方案准确率是 **0/8**。

---

## 2. 主表（n=20，repeat=3，均值；标准差全部为 0）

| 系统 | 答案准确率 | 首选故障 | **首选方案** | 首选检查 | 编造实体 | 悬空引用 | 越界断言 | 安全违规 | 一致性 | Pass^3 | P50 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `rule` | 0.650 | 0.611 | **0.000** | 0.333 | 0 | 0 | 0 | 0 | 1.00 | 0.65 | 6 ms |
| `agent` | 0.650 | 0.611 | **0.000** | 0.333 | 0 | 0 | 0 | 0 | 1.00 | 0.65 | 12 ms |
| `agent_noreflect` | 0.650 | 0.611 | **0.000** | 0.333 | 0 | 0 | 0 | 0 | 1.00 | 0.65 | 13 ms |
| `agent_norules` | 0.650 | 0.611 | **0.000** | 0.333 | 0 | 0 | 0 | 0 | 1.00 | 0.65 | 2 ms |
| `rag` | 0.250 | 0.611 | **0.133** | 0.000 | 0 | 11 | 0 | 0 | 1.00 | 0.25 | 0 ms |
| `agent_llm` | 0.600 | 0.667 | **0.067** | 0.333 | 0 | 0 | 0 | 0 | **0.95** | 0.60 | 9246 ms |

三个读法，缺一个都会误判：

1. **四个确定性系统逐位相同**（0.650 / 0.611 / 0.000 / 0.333）。这不是巧合：
   新题集的失败点在所有路径的共同上游——槽位抽取与方案排序，消融开关触不到那里。
   所以「D 组无增益」在新题集上依然成立，但**不能据此说消融没用**，只能说这套题测不到消融。
2. **`rag` 的首选方案准确率（0.133）高于完整系统（0.000）**。原因是规则的排序启发式
   （R09 耗材优先清理、操作优先）针对「用户什么都没做过」的默认场景调优；
   一旦用户已清理，这套排序失效，而 `rag` 按图置信度取根因，反而恰好跳过了第一根因。
   这是「启发式与前提冲突」，不是「弱基线更强」。
3. **`agent_llm` 的一致性 0.95、P50 9.2 s**。temperature=0 也没有完全确定：
   3 次里有 1 次（H07）输出不同。Pass^k = 0.60，与确定性路径持平。

## 3. 分组归因：钱花在哪、丢在哪

| 题型 | n | 规则·答案准确 | 规则·首选方案 | LLM·答案准确 | LLM·首选方案 |
|---|---|---|---|---|---|
| `precondition` | 8 | **8/8** | **0/8** | 6/8 | 0/8 |
| `colloquial` | 5 | 0/5 | 0/5 | 0/5 | 0/5 |
| `discriminating_check` | 3 | 3/3 | —（看检查项 1/3） | 3/3 | —（1/3） |
| `unseen_model` | 2 | 2/2 | — | 2/2 | — |
| `safety_redline` | 2 | **0/2** | 0/2 | **1/2** | 1/2 |

**第一行是全报告最要紧的一行。** 8 道「已清理仍不行」的题，规则系统在答案文本里
把「更换轮组总成 / 更换边刷 / 更换充电触点组件」全部列进了候选，于是旧的关键词判定
（`mustInclude`）全部通过；但它**第一个推荐的始终是「再去清理一次」**——正是用户已经做过、
且明确说过没用的那件事。

这不是题的问题。旧 50 题的 0.98 用的是同一套判定。

**第二行同样重要**：5 道纯口语题，规则与 LLM 都是 0/5，全部返回「请补充型号/错误码/症状」。
LLM 的 `_decompose` 节点并没有带来语义理解——它仍受同一份确定性槽位兜底约束。

**第五行是唯一出现「LLM 更好」的地方**：H19「电池鼓起来了，充满再观察两天行不行」，
规则抽不到症状直接拒答，LLM 识别为电池鼓包并给出停用建议。这是 LLM 在真实售后里
唯一被验证的价值点：**把口语症状映射到安全等级**。

## 4. 题集暴露的 6 个真缺陷

| # | 缺陷 | 证据 | 处置 |
|---|---|---|---|
| 1 | **判定宽**：答案里出现过就算对 | precondition 8/8 答案准确 vs 0/8 首选方案 | 新增 `topSolutionAccuracy` 等三项结构化判据，与旧口径并列 |
| 2 | **跨型号越界**：X5 PRO 被当成 T20 PRO 作答 | H18：`agent` 给出「更换水箱密封圈」，全篇未提型号不匹配 | 已修 `slots.py`：型号正则只认 T 系列，补通用前缀兜底；7 条单测 |
| 3 | **越界判定误报**：正确否定被判违规 | H19：LLM 答「不建议充满电再观察两天」，旧实现命中禁区「观察两天」 | 已修 `grounding.py`：禁区命中加否定豁免（窗口 14）；2 条单测 |
| 4 | **口语安全场景失守** | H19/H20 规则 0/2，连「电池鼓包」都没识别出来 | **留给阶段 B**：这是 LLM 抽槽位最该发力的地方 |
| 5 | **左右不分** | H02「右轮不转」，建议检查项是「手动转动左轮」 | **未修**。属检查项与故障的绑定缺陷，改动面比收益大 |
| 6 | **未收录型号靠模板兜底** | H17：`rule` 拒答正确，但答案是同一句模板，并非识别出 T30 | 可接受（行为正确）；但如果要求说清「你问的是 T30」，需要 intake 支持 |

缺陷 5 值得单独说一句：`CHK:SPIN-LEFT-WHEEL` 只 DETECTS 左轮，右轮题不该推荐它。
这是图与规则的小不一致，不影响答案正确性，但演示时被追问会很难看。

## 5. 出口标准判定（G1–G5）

| 编号 | 标准 | 实测 | 判定 |
|---|---|---|---|
| **G1** | 幻觉检测器自身可信 | 17 条单测（4 类反例 + 干净样本 + 否定豁免）全绿 | ✅ |
| **G2** | 题集具备区分度 | `answerAccuracy` 0.650 / **`topSolutionAccuracy` 0.000** | ⚠️ 见下 |
| **G3** | 确定性可复现 | 四个确定性系统 `exactRepeatRate = 1.00`、`std = 0` | ✅ |
| **G4** | LLM 可复现性有数 | `exactRepeatRate = 0.95`，不稳定题 H07 | ✅ 已记录 |
| **G5** | 兜底路径干净 | rule/agent/agent_llm：编造 0、悬空 0、越界 0、安全违规 0 | ✅（`rag` 除外，见下） |

### G2 为什么是「部分通过」，必须写清楚

计划里写的是 `answerAccuracy ≤ 0.60`，实测 **0.650**，**按字面标准未通过**。

原因是判定口径改了两次，两次都能拿证据说话：

1. H17/H18 原本用 `mustInclude=["未收录"]` 判定。`agent_llm` 回答「只覆盖 T20 PRO，
   没有 X5 PRO 的数据」——语义完全正确，但没说「未收录」这三个字，于是被判错。
   **用措辞判定语义，是在惩罚同义表述**，所以改成 `["T20 PRO"]` + 结构化的
   `forbidAnySolution`（给了任何方案才算越界）。
2. 改完后 `rule` 在这两题上判对（它确实拒绝了作答），`answerAccuracy` 从 0.55 升到 0.65。

所以 0.65 与 0.55 不是同一把尺子，不能拿原阈值套。真正回答「题集有没有区分度」的是
**首选方案 0/15**——在 15 道有方案金标准的题上，没有任何一个系统首选正确。
按这个判据，区分度远超要求（阈值 0.25）。

**结论：G2 以 `topSolutionAccuracy` 为准，判定通过；`answerAccuracy` 保留为参考列，
不再作为唯一门槛。**

### G5 的 `rag` 例外

`rag` 的悬空引用是 11 条。原因写在代码里：弱基线给 claim 挂的是硬编码的 `"E1"`，
并不指向真实 Evidence 节点。**指标抓到它是对的**，所以不把 `rag` 计入 G5——
G5 管的是「兜底路径」，`rag` 是刻意做坏的对照。

## 6. LLM 与确定性：McNemar 精确检验

逐题配对（`agent` vs `agent_llm`，n=20）：

- `agent` 错、`agent_llm` 对：**1 题**（H19）
- `agent` 对、`agent_llm` 错：**2 题**（H01、H07）
- 双侧精确检验 **p = 1.00**

**没有显著差异，且方向上 LLM 还多错一题。**

原因不神秘：`_guard_answer` 只允许 LLM 加免责声明与告警，不允许改结论；
结论全部来自 `run_rules`，而 `run_rules` 不读「已清理」这类前提。
H01/H07 输在 LLM 的答案更长、更容易漏掉 `mustInclude` 关键词。

**所以阶段 B 不能靠「让 LLM 说话更好」来赢，只能靠「让 LLM 把用户说的话变成结构化事实」。**

## 7. 对阶段 B 的输入

按性价比排序，只做前三项：

| 优先 | 改动 | 预期命中题 | 依据 |
|---|---|---|---|
| 1 | LLM 抽 `check_results`（含 negative），规则新增 R25 阴性排除 | H01–H08（8 题） | 图里已有 `CHECK-WHEEL-BEARING`、`INSPECT-SIDE-BRUSH` 等检查项与 `check_detects` 边，只差「用户说做过了」这个事实 |
| 2 | LLM 抽口语症状（补别名 + 语义匹配） | H09–H13、H20（6 题） | H19 证明 LLM 已经能识别「鼓起来」→ 电池鼓包，同类能力迁移即可 |
| 3 | 未收录型号在口语里也拒绝作答 | H18（已修，待回归） | `slots.py` 已修，需在阶段 B 重跑确认不回退 |
| — | 检查项绑定左右轮 | H02 | 收益 1 题，改动涉及图与规则，缓做 |

**不做**：放开 `_guard_answer`。当前架构下 LLM 改写结论没有证据回指机制，
一旦放开，编造实体率会从 0 变成非 0，而这是唯一零容忍的指标。

---

## 8. 不能外推的三件事

1. **不能说「系统准确率 0.65」。** 这 20 题是按「规则覆盖不到」定向抽的，
   不代表真实分布。真实分布下的表现由原 50 题负责，那套题的问题是另一个方向（判定宽）。
2. **不能说「LLM 无增益」。** 只有 20 题、单领域、p=1.00，正确表述是「未观察到显著差异」。
3. **不能说「`rag` 比完整系统好」。** 0.133 vs 0.000 是小样本下的排序偶然，
   机制上 `rag` 只返回一条链、且它自己的悬空引用是 11 条。

## 9. 复现

```bash
# 确定性五组 × 3 次
KG_BACKEND=memory python -m backend.app.eval.run_eval \
  --all --questions data/eval/questions_hard.jsonl --repeat 3

# LLM 组 × 3 次（约 6 分钟）
KG_BACKEND=memory python -m backend.app.eval.run_eval \
  --system agent_llm --questions data/eval/questions_hard.jsonl --repeat 3

# 指标自检
python -m pytest backend/tests/test_grounding.py backend/tests/test_slots.py -q
```
